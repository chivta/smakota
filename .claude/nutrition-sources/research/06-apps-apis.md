# Track 06: Calorie-tracking apps and commercial nutrition APIs/vendors

Scope: where FatSecret and competing calorie apps source their food data, plus commercial nutrition
data vendors and product-data syndicators a bot could plug into directly. Spot checks against
`products.txt` (two weeks of the user's real FatSecret diary) are marked in the last column.

Note on method: several vendor sites (Nutritionix, FatSecret's own consumer site in places) sit
behind Cloudflare/JS gates that return redirects or blank pages to `curl`; where that happened I
relied on search-engine snippets and cross-referenced official help/pricing pages, and say so below.
Open Food Facts' legacy `cgi/search.pl` endpoint intermittently returned non-JSON (rate limiting)
during this session; counts from it are one-off samples, not stable.

## Notes

**FatSecret.** The Platform API's own documentation (`platform.fatsecret.com/api-editions`, `.../platform-api`) is the clearest, most complete public statement of how the database is assembled: a mix of official government nutrition tables, brand/restaurant-submitted data via "FatSecret Brand Tools," and community submissions that go through staff verification before publishing — i.e., not an open crowdsource, closer to a moderated wiki. Country/dataset breadth (56+ countries, 26 languages per vendor marketing pages) is the main differentiator between the free Basic/Premier-Free tiers (US only) and paid Premier (rest of world, including presumably Ukraine/Russian-language entries, though the vendor pages don't break this out by country). A live search on fatsecret.com's own consumer site turned up "Яготинське" entries, confirming Ukrainian dairy brands exist in their live dataset even if the exact tier/dataset boundary isn't publicly documented.

**MyFitnessPal.** Its developer API portal (`myfitnesspal.com/apps/api/version`) states it is not accepting new API access requests — this has been the case for years and nothing found in 2026 sources suggests it has reopened. A bot cannot legally source MFP's food data; the ~20M-food number is a vendor marketing figure with no way to verify size or Ukrainian coverage independently.

**Cronometer.** NCCDB is a paid, proprietary academic dataset (University of Minnesota Nutrition Coordinating Center) that Cronometer licenses — it is not something Cronometer redistributes or exposes via any public API. The CRDB user-contributed layer is moderated by Cronometer staff before going live, similar to FatSecret's model.

**Apple Health / Google Fit / Health Connect.** These are included in the brief but are architecturally *not* food-data sources — HealthKit and Health Connect only define nutrition data *types* for other apps to write into a shared store; there is no catalogue of foods to search. Any calorie bot would use these only as a diary sync target (writing what it already resolved from a real food database), never as the source of truth for nutrition values.

**GS1 / GS1 Україна.** This is a common point of confusion worth flagging explicitly: "Verified by GS1" is a barcode/brand-identity verification lookup (does this GTIN belong to this company, and here's the product name/image), not a nutrition-facts feed. Full nutrition information travels over GDSN, a closed B2B network requiring a paid data-pool subscription and a trading-partner relationship — not something a bot can query as an outside party, and GS1 Україна's own public pages (gs1ua.org) describe barcode assignment and the Verified by GS1 registry, not a public nutrition API.

**Syndigo/1WorldSync, NielsenIQ Brandbank/Label Insight, Salsify.** All three are enterprise B2B product-content platforms sold to brand owners and retailers, not public data sources. They were included in the brief as vendors that *exist* in this space, but none offer a self-serve or public API a hobby calorie bot could use — access requires being a retailer/brand under contract. Salsify in particular is PIM software (the client's own catalogue tooling), not a shared database at all.

**Open Food Facts.** The most directly useful open source for Ukrainian packaged-goods barcodes: crowdsourced, so coverage of any specific product is not guaranteed, but a spot check during this session found "Торчин Кетчуп Лагідний" — a direct hit against a diary item logged twice. Coverage of Ukrainian *dish-style* and restaurant items (borscht, shaurma, KFC menu items, etc.) is essentially nil since those aren't barcoded retail products. The `cgi/search.pl` legacy endpoint returned malformed responses partway through this session (likely rate-limiting my repeated requests); the `/api/v2/search` endpoint was stable and is the one to prefer going forward.

**USDA FoodData Central.** Public-domain (CC0) and free with a data.gov key, but Branded Foods entries are almost entirely US-labeled products — it will resolve generic dishes (chicken breast, borscht-adjacent generic entries) but essentially no Ukrainian retail brand names. The public `DEMO_KEY` used for this session's spot check returned empty results, likely due to demo-key-wide rate limiting rather than the query being wrong; a registered personal key should be requested before relying on this for development.

**OpenNutrition.** Confirmed via direct download (`opennutrition-dataset-2025.1.zip`) in a prior pass of this research: ODbL-licensed, TSV format, cross-referenced to USDA/CNF/AUSNUT/FRIDA records with full micronutrient panels. It is a generic-food composition dataset (like a USDA/CNF remix), not a barcode/retail-brand database, so it will not resolve Ukrainian packaged goods — useful only as a free, redistributable base layer for generic dishes and raw ingredients.

**Nutritionix.** The pricing/API pages are behind Cloudflare and returned redirects/blank content to `curl` in this session; pricing figures above come from third-party summaries (calorieapi.com, spikeapi.com) rather than Nutritionix's own page text, so treat the specific dollar figures as approximate until confirmed against `nutritionix.com/business/api` directly (which did load in a browser context per search snippets, just not via curl). An unauthenticated call to the live `trackapi.nutritionix.com` endpoint correctly returned HTTP 401, confirming the API is real and key-gated.

**Fitatu.** Polish-market app; found no evidence of a Ukrainian-language database variant, only PL/EN/NL/FR/IT/DE/ES. Given Fitatu's user-typed-from-label crowdsourcing model, Ukrainian products specifically sold in Poland (common for Ukrainian refugees/diaspora) could theoretically appear as user submissions, but this isn't a documented feature and wasn't verified.

**«Худеем вместе» / «Худеем за неделю».** A Russian-market app family; found only marketing descriptions, no data-source documentation and no public API. Flagged as legally uncertain for a bot serving a Ukraine-based user, separate from the pure data-provenance question — worth a deliberate decision rather than silent inclusion.

**AI photo apps (Cal AI, SnapCalorie, Calorie Mama).** These split into two very different models worth not conflating: Cal AI's photo path returns a vision-model *estimate* with no underlying database row at all (per its own review coverage), while its manual-search path draws on a separate ~2M-food catalogue of unstated origin. SnapCalorie's API is similarly a proprietary vision-analysis endpoint, not a queryable catalogue. None of the three publish what base nutrition tables (if any) ground their model outputs, so "data origin" for the photo-estimate feature specifically is opaque — that itself is a meaningful finding, not a gap in my research.

## Dead ends

- **MyFitnessPal API** — public developer program is closed to new applicants; no legal path for a bot to pull its database.
- **Lose It! API** — no public developer API found at all, verified-vs-crowdsourced split not separately accessible.
- **YAZIO, Lifesum, Noom, Fitatu, MacroFactor, Carbon, «Худеем вместе», Cal AI, Calorie Mama** — all consumer apps only, no public food-database API found for any of them; Carbon's data is FatSecret's under a different label, so it collapses into the FatSecret row rather than being an independent source.
- **Apple HealthKit / Google Health Connect / Google Fit** — no food catalogue exists in either; they are diary-sync targets, not nutrition sources.
- **GS1 Verified by GS1 (public tool)** — confirms brand/GTIN identity only, not a nutrition-facts feed; full nutrition sits behind the closed GDSN network.
- **Syndigo/1WorldSync, NielsenIQ Brandbank/Label Insight, Salsify** — enterprise B2B platforms with no self-serve or public tier; inaccessible without a retailer/brand contract.
- **USDA FoodData Central for Ukrainian products** — public-domain and free, but Branded Foods is US-label-driven; essentially no Ukrainian retail SKUs will resolve.
- **OpenNutrition for Ukrainian products** — same limitation as USDA: strong generic/composition-table coverage, no barcode-level Ukrainian brand data.
- **Kaggle "Ukraine - Food Prices" dataset** — despite the name, it contains prices, not nutrition values; a dead end for this project's purpose specifically.
- **Nutritionix pricing/terms pages via curl** — Cloudflare-gated; had to rely on search-engine summaries rather than the vendor's own page text for exact pricing (the API endpoint itself was independently confirmed live and key-gated).
