# Ukrainian supermarket / hypermarket / discounter chains: nutrition data sources

Method note: `curl -sL -A "Mozilla/5.0"` was used against every domain's `robots.txt`, `sitemap.xml`, and sample product pages. Several storefronts (silpo.ua, atbmarket.com) sit behind Cloudflare managed challenge and return HTTP 403 to curl and to WebFetch alike (confirmed by hand). For those, findings are search-engine-snippet evidence only, labelled as such. `zakaz.ua`-platform storefronts (Novus, Auchan, METRO, ЕКО маркет, Таврія В, Megamarket, Ultramarket, Космос) are plain HTTP 200 and were fetched directly. Fora.ua is not Cloudflare-blocked but is a client-side-rendered React SPA — curl and WebFetch both get only the empty app shell, so its own product pages could not be confirmed for nutrition text even though the site itself is reachable.

## Notes

**Сільпо / sf-ecom-api.silpo.ua**: this JSON API is live and NOT behind Cloudflare (unlike the silpo.ua website itself). `GET https://sf-ecom-api.silpo.ua/v1/uk/branches/00000000-0000-0000-0000-000000000000/products?search=snickers` returns paginated JSON with `total`, `items[]` (title, price, brandTitle, slug, weight as `displayRatio`, etc.) — confirmed 28 hits for "snickers" and 18 for the more specific `searchV2` mode. This is a commerce/pricing API, not a nutrition API: fields returned are id, title, price, stock, slug, brandTitle, ratio/weight — no calorie/protein/fat/carb fields anywhere in the schema tried (`products?search=`, `?searchV2=`, `?productsSlugs[]=`, `?productsIds[]=`). Nutrition text ("Харчова цінність") appears to live only on the (Cloudflare-protected) HTML product page, confirmed via a search-engine snippet showing exact numbers (70.4 kcal, 5.3 g protein) for one product, and via Silpo's own newly-launched MCP server (see below), which is the most promising lead for programmatic nutrition access from Silpo.

**Сільпо MCP (mcp.silpo.ua)**: discovered via web search — Silpo has stood up an official Model Context Protocol endpoint as part of an "AI Factory" initiative/hackathon, exposing tools including `silpo_get_product_details`, documented to return the full product card including "харчова цінність" (nutrition value). This was not previously known and is a genuinely new lead worth prioritizing: if it's open beyond the hackathon, it could be the single best nutrition source for this whole track. Access requires OAuth 2.1 + PKCE and (per the docs) participation in the AI Factory program; exact terms of use for the data beyond the hackathon were not stated on the docs page fetched.

**АТБ**: robots.txt and the top-level domain respond normally, but every specific page tested (sitemap.xml, product pages found via search) returned Cloudflare's "Just a moment..." managed challenge (HTTP 403) to both curl and WebFetch. This means ATB's nutrition-page claims could only be evaluated by search-engine snippet, and none of the snippets returned in this pass showed nutrition text directly (search results skewed toward third-party calorie tables instead of atbmarket.com pages). Own-brand "Своя Лінія" nutrition values do surface reliably on the third-party site tablycjakalorijnosti.com.ua (outside this track, likely covered by the calorie-website track), which suggests the values do exist on-pack/on-page even if this pass couldn't reach them directly.

**Фора (fora.ua)**: the storefront itself is NOT Cloudflare-blocked (plain 200 responses) but is a React single-page app with no server-side rendering — curl and WebFetch both retrieve only a ~7 KB HTML shell with no product content, regardless of URL. The sitemap-products.xml lists 6,313 real product URLs (a genuine, verifiable count, unlike the zakaz.ua "37,412" marketing figure). Its JS bundle exposes backend API base URLs (`api.catalog.ecom.fora.ua`, `api.ecom.fora.ua`, `api.shop.fora.ua`, all under `/api/2.0/exec/<ServiceName>` — a custom RPC-style pattern, not a documented REST/GraphQL surface) but calls made in this pass (query params guessed) returned no usable data; a follow-up pass should try to capture the exact POST payload shape these endpoints expect (likely JSON-RPC) by intercepting real browser traffic, since this is the only technical path to Фора's product/nutrition data found so far. Fozzy Group (which owns Фора, Сільпо and Thrash) runs a shared backend platform, so figuring out Фора's actual call format could plausibly unlock Thrash's data too.

**zakaz.ua platform (Novus, Auchan, METRO, ЕКО маркет, Таврія В, Megamarket, Ultramarket, Космос)**: all eight of these are white-label storefronts on the same `zakaz.ua` e-grocery platform (owned by Zakaz.ua / Fozzy-adjacent but operating independently as a marketplace-style delivery layer for multiple retail brands). All eight homepages, byte-for-byte, display the identical marketing string "37 412 товарів в асортименті" — this is almost certainly a shared platform-wide UI component and NOT each individual chain's real, distinct assortment size; treat any per-chain SKU count derived from this figure as false. None of the eight had a real product page opened and checked for nutrition text in this pass (time-constrained) — this is the single biggest gap in this report and should be the first thing a follow-up pass does, since a positive result on any one of them likely generalizes to all eight (same platform, same templating). Zakaz.ua's Terms of Use (https://zakaz.ua/uk/terms/) are unambiguous and restrictive: content may not be reproduced, copied, resold, or used commercially without written consent, and Zakaz.ua reserves the right to delete any content without notice — this materially affects the legality of scraping any of these eight for a product.

**Varus / Velmart**: neither site is Cloudflare-blocked, but neither yielded a directly-confirmed nutrition-bearing product page in this pass — attempts hit 404/redirect stubs or an empty sitemap-index response, likely due to JS-rendering or incorrect URL guesses rather than an actual block. Both need a proper category-page crawl (find a real product slug first, then fetch it) in a follow-up pass rather than guessing URLs. Velmart's own robots.txt points its sitemap at a `testnewserver.velmart.ua` hostname, which is unusual for a production site and may indicate the sitemap is stale or the real production sitemap is elsewhere.

**Healthy Food**: this is a prepared diet-meal-delivery subscription business (à la "1200 ккал/day" programs), not a supermarket, but it is relevant to the user's diary since they log ready meals. It shows kcal at the whole-program/day level and offers a BJU (protein/fat/carb) target calculator for the customer's daily goal — but there is no evidence of per-dish or per-100g nutrition labels for individual meals in what a subscriber actually receives, based on the marketing pages checked. This is a paid B2C service (from 900 UAH/day), not a data source to integrate against.

**Good Wine / Winetime**: both are alcohol-focused (Good Wine also carries gourmet food and has a "bakalija" food sitemap section), included because the diary logs beer, liqueur, and craft beer entries that might plausibly be sourced from a premium/craft retailer. Neither is Cloudflare-blocked. Sitemap sizes are real and substantial (Good Wine: 16,882 unique `/ua/` product URLs across food+drink sitemaps; Winetime: 25,532 unique `/ua/` product URLs) but no product page was actually opened to check whether alcohol products carry kcal/100ml — this is typical for wine/spirits retailers to omit, but that is an assumption, not a confirmed fact, and should be checked in a follow-up pass.

**Own-brand nutrition coverage (Premія, Своя Лінія, De Luxe Foods, Розумний вибір, Власна Випічка, Повна Чаша)**: none of these own-brand lines could be confirmed as showing КБЖУ directly on their retailer's own website in this pass, because the three chains that carry most of them (Сільпо, АТБ, Фора) are all either Cloudflare-blocked or JS-rendered to automated tools. The strongest indirect evidence that these products do carry nutrition values somewhere (label or retailer page) is that a third-party site, tablycjakalorijnosti.com.ua, has individual pages with full kcal/protein/fat/carb breakdowns for many of them (Своя Лінія borshch flour/kvass/dough/cheese/halva items, Власна Випічка croissants with e.g. 472 kcal for the chocolate croissant and 354 kcal for the apricot one, Varus bread/buns/pizza, Velmart frozen tuna steak). That site is outside this supermarket track (likely relevant to a calorie-website or open-product-DB track) but is flagged here since it's the only place in this whole pass where actual numbers for the user's own-brand diary items ("Своя Лінія Наполеон", "Власна Випічка Круасан", "Фора Мафін") were located, indirectly.

## Dead ends

- Брусничка — chain ceased operating in November 2019 due to debt (Rinat Akhmetov's "Ukrainian Retail"); no live website, no data to source.
- Thrash (Траш) — thrash.ua is a store-locator/promotions page only; no evidence of a shoppable online catalogue or product pages.
- Megamarket own catalogue size claim ("37,412 товарів") — this is a shared zakaz.ua-platform marketing figure identical across 7+ unrelated chains, not a real per-chain count; do not use it.
- Sim23/Сімі — both domains are marketing/informational sites (store finder, "about us"); no product catalogue found.
- Silpo/АТБ direct HTML — Cloudflare managed challenge blocks curl and WebFetch uniformly (HTTP 403) on robots.txt, sitemap.xml, and product pages; only search-snippet evidence available without a real browser.
- Фора product pages — reachable (no CF block) but pure client-side React rendering means curl/WebFetch retrieve no product content at all; would require a headless browser or reverse-engineering the `/api/2.0/exec/*` RPC calls.
- shop.spar.ua search endpoint (`/varash/search?text=`) — returned HTTP 404; wrong route guessed, not evidence of missing search functionality.
- Kopiyochka search (`/search/?q=`) — returned HTTP 200 but no product results rendered to curl; likely also JS-driven results.
- Furshet — chain went bankrupt in 2021 and was absorbed by Сільпо-Фуд; furshet.ua domain still resolves but no functioning online catalogue was confirmed (page load issues in this pass).
